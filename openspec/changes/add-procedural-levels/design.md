## Context

当前游戏只有一关（`src/data/levels/level1.ts`），`GameScene` 在字段初始化处硬编码 `new World(level1)`。通关后 `won=true`，HUD 提示"按 R 再来一次"，`R` 只是 `world.restart()` 同一关——既没有"下一关"概念，也没有关卡列表。

引擎层的关键事实：`World` 只认 `LevelData` 这一个接口（`{ tiles, playerSpawn, goal, enemies, coins, ... }`）。`CollisionWorld`、所有实体（`Player`/`Enemy`/`Coin`/`Goal`）、`Physics`/`Collision` 系统都围绕它工作。**只要生成器最终产出合法 `LevelData`，引擎层与现有 81 个测试完全无感。**

另一关键事实：`src/world/LevelValidation.ts` 已实现 `computeMaxJumpHeight`（物理仿真精确最大跳跃高度 ≈144px≈3 格）、`extractPlatforms`（提取可站立平台）、`horizontalReachAtHeight`（给定高差的水平可达距离）、`validateLevel`（从地面 BFS 传播可达性 + 终点邻接检查）。**这正是程序化生成需要的可行性原语。**

约束：纯前端 H5、无后端、固定步长物理（1/60s）、PixiJS 6 渲染。

## Goals / Non-Goals

**Goals:**

- 运行时纯生成关卡，给定 `(seed, levelIndex)` 确定地产出**合法且可解**的 `LevelData`，无需手作。
- 8 关一场的"run"进度模型 + 命数系统 + 过关/通关/新场流程。
- **多样性优先于难度递增**：每关体验不同，但无任何一关系统性更难。
- 纯跳跃即可通关（构造性可解），冲刺/蹬墙跳为可选捷径。
- 生成结果**可复现、可测试、可调试**（seeded）。
- 引擎接口 `LevelData` 零改动 → 现有测试零回归。

**Non-Goals:**

- 不做无尽/随机模式的"卖点级"打磨（目标是内容供给，非复玩性核心）。
- 不强制玩家使用冲刺/蹬墙跳（不把高级技巧设为通关依赖）。
- 不建模冲刺/蹬墙跳的可达性（验证器与生成器都只用纯跳模型）。
- 不做关卡编辑器、不做种子分享 UI、不做成就/排行榜（可选未来）。
- 不引入 checkpoint（列为 playtest 观察点，必要时另起 change）。
- 不保留手作多关（连第 1 关也由生成器"安全预设"产出，真正零手作）。

## Decisions

### D1. 生成 = 验证的反问题；复用 `LevelValidation` 原语

生成器不另起一套可达性逻辑，直接调用 `computeMaxJumpHeight` / `extractPlatforms` / `horizontalReachAtHeight` / `validateLevel`。

- **理由**：可达性数学已在验证器中用物理仿真精确实现，复用避免重复与漂移；生成时"按可达包络构造"→ 产出必然通过 `validateLevel`。
- **备选（否决）**：在生成器内重写可达性——会与验证器逻辑分叉，长期不一致。
- **代价**：验证器只建模纯跳（见 D8），生成器随之保守——但这正是 Non-Goal 的"纯跳可达"。

### D2. 两层生成模型：连续地面 + 挖坑 + 浮空台（Model B）

与 `level1` 同构：底层一条连续实心地面，在地面中"挖坑"（掉穿 = 出界 = 死，匹配 `player.y > worldHeight → restart`），地面上方放置浮空台承载垂直感/敌人/金币。

- **理由**：地面天然连通一切触地之物 → 可达性近乎免费；坑是显式、可见、公平的危险源；与 `level1` 美学一致；掉坑死亡与现有引擎死亡逻辑一致。
- **备选（否决）**：踩石过虚（Model A，平台是唯一地面、处处悬崖）——太硬核、与 `level1` 不像、与"舒适不递增"目标相悖。
- **可达性含义**：地面 BFS 自连通；浮空台按构造放在地面（或另一块已可达浮空台）的跳跃包络内 → BFS 必达。`validateLevel` 作兜底。

### D3. 骨架 + 装饰（Skeleton + Decoration）分离

- **骨架（地面层）**：连续地面 + 挖坑。只管"主路径一定走得通"。坑宽/坑距/起跑落地空间受硬约束（D7），构造保证可跨。
- **装饰（浮空台层 + 实体）**：在已可达锚点上挂浮空台、敌人、金币。只挂载到"已可达"集合，永不破坏可解性。
- **理由**：可解性（骨架，硬约束）与趣味性（装饰，可调参数）解耦——调装饰手感不会把关卡调坏成不可解。调参面缩到最小。
- **备选（否决）**：一体化生成——调任何参数都可能破坏可解性，回归脆弱。

### D4. seeded PRNG（mulberry32）

所有随机性来自 `mulberry32(seed ⊕ levelIndex)`，不用 `Math.random`。

- **理由**：可复现（同 seed 同关卡，死掉重开 layout 一致 → 公平可学）、可测试（单测对固定 seed 断言）、可调试（复现 bug）。整局可复现性是 seed 模型的红利。
- **备选（否决）**：`Math.random`——不可复现、不可测、死掉重开 layout 变化导致不公平。

### D5. Run 模型：固定本场 seed，布局即函数，不存储

一场游戏开局掷一个 `seed`，本场 8 关 = `gen(seed, 1..8)`。**关卡布局是 `(seed, levelIndex)` 的纯函数**——不存储布局，每次按需重算。持久化的运行时状态只有 `{ seed, currentLevel, lives, score }`。

- 流程：到终点 → `currentLevel++`；死亡 → `lives--` + 重开当前关（重算 `gen(seed, currentLevel)`，layout 一致）；`lives===0` → `currentLevel=1`（回本场第 1 关，同 layout）；`currentLevel>8` → "全部通关" → 开新场（新 seed）。
- **理由**：纯函数布局让"重开同 layout"免费实现，且整局可重放。
- **备选（否决）**：生成后存储布局数组——多余的状态、丧失纯函数的优雅与可复现红利。

### D6. theme 塑造结构 + 跨 theme 压力等价

4 个 theme（平原 / 洞穴 / 高塔 /密集），每个 theme 是一组生成参数带（`pitDensity` / `enemyDensity` / `floatDensity` / `verticality` / `width`），**直接驱动游走器与装饰器的分布行为**（结构塑造，非仅装饰）。

- **跨 theme 压力等价**：每个 theme = "一种强压力 + 别处刻意放低"，总难度持平（如洞穴坑多但敌人极少；高塔垂直操作强但坑极少）。满足"不同但不递增"。
- **可断言**：定义粗略难度估算 `Σ(density×权重)`，单测断言 4 个 theme 估算值落在同一带 ±15%。
- **theme 选择纪律**：第 i 关 theme ≠ 第 i-1 关 theme（不连续重复）；第 1 关不走 theme，走"安全预设"（D10）。
- **理由**：用户核心诉求是"每关不同"——结构/视觉差异比装饰密度差异显眼得多。等价交换压力避免滑向"更难"。
- **备选（否决）**：theme 仅改装饰密度——感觉像换皮；或难度递增——违反用户目标。

### D7. 坑可跨性硬约束（纯跳可达）

每个坑强制：① 宽 ≤4 格（常规 ≤3，4 格仅作罕见"挑战坑"注入）；② 坑前 ≥2 格平整地面（保证满速起跳，因玩家需 ~1 格加速到 `maxMoveSpeed`）；③ 坑后 ≥1 格落地平台。

- **理由**：`horizontalReachAtHeight(0)≈213px≈4.4 格`假设满速起跳；起跑距离常被忽略却决定真实可达性。三约束合一 → 纯跳必可跨，且"给助跑空间"本就是好手感。
- **备选（否决）**：允许更宽坑并依赖冲刺跨——违反纯跳可达原则。

### D8. 保守可解：纯跳跃模型，冲刺/蹬墙跳为可选捷径

生成器与验证器一致只用纯跳可达模型。

- **理由**：永远安全（验证器判可达 = 实际可达）；冲刺/蹬墙跳作奖励高级操作，不设为依赖。
- **代价**：验证器欠近似（不建模冲刺/蹬墙跳）→ 可能生成"其实可用高级技巧到达"却仍按纯跳设计的路径——保守但安全。未来若要更激进，需扩展验证器建模高级技巧（另起 change）。

### D9. 金币即导航语言（非随机撒点）

金币放置分三类，各有职责：① **跨坑金币弧**——沿跳跃抛物线排列，指示跳跃轨迹（自带教学）；② **主路径金币串**——面包屑，引导主行进方向；③ **浮空台分支金币**——诱惑探索。**绝不独立随机撒点。**

- **理由**：生成关卡没有设计师在场指路；金币是唯一的自我导航工具。随机金币会误导（不可达的孤币让人困惑、错误弧线的金币引人撞墙）。
- **备选（否决）**：均匀随机撒币——误导、降低关卡可读性。

### D10. 第 1 关走"安全预设"（非 theme 轮）

第 1 关固定参数：40 格、`pitDensity≈0.1`（最多 1 个 ≤2 格小坑）、`enemyDensity≈0.1`（最多 1 敌人且远离出生点 ≥5 格）、浮空台少而低。比任何 theme 都软。

- **理由**：零门槛入场，玩家先建立手感再进 theme 轮。这是"地板"不是"第 1 级台阶"，不违反"不递增"。
- **备选（否决）**：所有关同分布——首关可能开门杀，劝退。

### D11. 失败兜底链（确定性）

`validateLevel` 理论必过（构造保证），但工程兜底：① 段重掷（用子 seed 重掷违规段，≤5 次）→ ② 安全预设参数重生成整关 → ③ 内置 known-good 模板关 + `console.warn`。永不崩。

- **理由**：确定性 seed → 失败可复现可测；单测对大量 seed 断言"永不走到 ③"，CI 守底。

### D12. 引擎接口 `LevelData` 不变

生成器输出 `LevelData`（像素），与 `level1` 同形。`World`/`CollisionWorld`/实体/测试零改动。

- **理由**：零回归。手作格式简化（早期 `docs/level-system-design.md` 设想的 ASCII 图例）因"纯生成、零手作"而基本消解——不再需要人类友好的编写格式。
- **代价**：生成器内部用瓦片坐标运算、产出时转像素——一层薄转换，可接受。

## Risks / Trade-offs

- **[长关 + 全重开挫败感]** 60–80 格关卡死亡后整关重玩，损失面大于短关 → **Mitigation**：列为 playtest 头号观察点；若实测不佳，后续 change 加 checkpoint（不属本次）。
- **[首版生成"能玩但平庸/机械感"]** 纯生成平台关的客观规律——可解能保证，"好玩"只能迭代 → **Mitigation**：骨架+装饰已把调参面最小化；预期首版后用几轮调 theme 参数带到顺手。
- **[theme 压力等价是启发式]** 难度估算函数未必完美反映主观感受 → **Mitigation**：单测断言粗估持平 + playtest 微调参数带。
- **[验证器欠近似]** 不建模冲刺/蹬墙跳 → 关卡偏保守、可能"看似能更难" → **Mitigation**：保守即安全；激进路线需另起 change 扩展验证器。
- **[换关时 Pixi 资源残留]** `GameScene` 切关需销毁旧 `World.root` → **Mitigation**：`world.root.destroy({children:true})`；`World` 不持有全局监听（监听在 `InputManager`，scene 级安全）。
- **[确定性 seed 的失败重放]** 若某 seed 必失败 → 该 seed 永远走兜底 → **Mitigation**：兜底本身确定可测；CI 对大样本 seed 守底。

## Migration Plan

分阶段、每阶段独立可交付/可测：

1. **生成器内核（无游戏集成）**：`rng` + 类型 + 地面层 walker + 浮空台装饰 + `generateLevel` + themes + 兜底。纯函数 + 单测（多 seed 全过 `validateLevel`、可复现性）。
2. **进度系统**：`LevelProvider`（run 模型 + 命数状态）+ 单测。
3. **集成**：`GameScene` 按 provider 取关/换关；`Hud` 显示关卡/命数；`BootScene` 注入 provider。
4. **联调 + playtest + 调参**：跑通整局、调 theme 参数带到顺手。

**Rollback**：变更可加性，全部在 provider 之后；回退只需把 `GameScene` 改回 `new World(level1)`。

## Open Questions

- **theme 参数带的精确值**：design 给出初值（见 tasks/specs 引用），最终需 playtest 微调（参数带是纯数据，调整不动算法）。
- **第 1 关是否值得手作**：design 推荐"安全预设生成"（零手作）；若 playtest 觉得首关需要更强教学控制，可后续改为 1 个手作 intro（不影响架构，provider 第一项可手作）。
- **checkpoint 必要性**：deferred 到 playtest 后评估。
- **theme 数量**：4 个起步，8 关会重复；若 playtest 觉得重复感强，扩充 theme（纯数据，不动算法）。
